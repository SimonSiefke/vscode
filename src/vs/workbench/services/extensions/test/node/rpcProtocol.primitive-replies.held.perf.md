# Held native primitive-reply experiments

All prototypes remain unshipped. They compare the exact current `38b2` RPC implementation with native primitive replies, string-only native replies, and string replies plus synchronous primitive-return handling. Ordinary byte/error/cancellation/binary controls retain their paths. Matching esbuild ES2024/decorator settings compile both sides, using actual Node MessagePorts and Electron renderer/utility-process MessagePorts with the product 8 KiB Node Buffer pool. Every round-trip fixture is checked.

The initial comparison uses eight randomized process blocks with three measured batches per fixture, at concurrency 1 and 32. Native replies avoid JSON stringify/parse for primitives and normalize numbers to their legacy JSON values. Node sequential text improves 25.17%, but ordinary renderer sequential numeric/small-object fixtures regress 5.70%/13.74%; Node burst small objects regress 8.84%. All four complete datasets and every control remain retained.

A separate four-block pilot loads before, string-only and string-plus-sync variants in one renderer/utility process pair, warming all fixtures before measurement. It randomizes fixture and variant order to reduce process-startup effects. String-only renderer sequential 4 KiB, 64 KiB and escaped text improves 13.54%, 15.31% and 19.06%, respectively. Some controls still regress: asynchronous workspace edits +9.63%, burst settings +8.96% and burst small objects +8.70%. The synchronous primitive-return variant regresses several ordinary renderer controls and is also held. These pilots are correlated component measurements, not whole-product gains.

The ordinary/mixed regressions remain unresolved. These are retained alongside gains rather than selected away. Two new native string-format assertions are red on the baseline; their source is preserved with the unshipped prototype and is not added to the production test inventory. The original RPC tests remain enabled. No result here establishes progress toward the requested 10–20% complete smoke-suite target.

The accompanying JSON contains all eight complete datasets, exact selected and held sources, renderer/utility/Node harnesses, randomization scripts and control results. The separate-process first comparison and shared-process pilot are separate designs and must not be pooled into a single percentage.
