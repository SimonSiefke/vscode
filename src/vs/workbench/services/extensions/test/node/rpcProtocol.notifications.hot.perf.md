# Notify high-volume file, data-channel and theme updates

A memory-only RPC trace of the actual packaged `38b2` product finds 616 ordinary requests across three launches in two real smoke scenarios: 443 file-event deliveries, 41 file-provider information updates, 126 data-channel deliveries and six theme updates. Both profiled smoke cases pass without retries. These are diagnostic traffic counts, not timing or whole-product speedup claims. The inspector/profiler changes scheduling, and elapsed times from those runs are not performance samples.

All four receiver methods return void. Every production call site was inspected: file-system and data-channel callbacks fire ordinary events; provider-info callbacks update an in-memory capability map; theme callbacks update the current theme and fire its event. Their callers ignore remote completion. The accompanying JSON records source hashes and every diagnostic protocol summary. No request/response payloads or credentials are logged.

Add the four methods to the existing explicitly opted-in notification path. FIFO delivery, JSON snapshots, binary/cancellation fallback, error reporting and periodic ordinary liveness probes retain the existing protocol implementation. There is no new codec, framing or batching policy. Binary and wrapped data-channel arguments that need the mixed codec still use ordinary RPC.

The new integration case uses real RPCProtocol/RPCMessagePort endpoints and actual file-system receivers. Provider capabilities and a queued file event must be visible before a subsequent ordinary RPC barrier; mutating the queued event must not alter its snapshot. On the baseline it records two unnecessary empty replies and fails. With the opt-ins, it records no such replies and passes with the same event and metadata assertions.

Validation: 249 selected Node tests, 1,341 combined Electron/API tests (three pre-existing pending), full client typechecking and focused lint pass. Existing byte/socket tests remain applicable because their source and wire format do not change. Whole-suite comparisons for this new change remain pending; the completed preceding eight-pair candidate result is −1.98%, short of the requested 10–20% target.
