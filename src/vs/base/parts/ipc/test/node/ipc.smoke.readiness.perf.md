# Correct the Local chat benchmark readiness race

The original harness can submit its first prompt into a startup Local session before `smoketest.openLocalChat` finishes starting the requested fresh Local session. Command-palette dismissal and the first changed `data-bound-chat-resource` do not prove explicit command completion. A bounded model-state diagnostic records one request in the outgoing model followed by an empty replacement model. The old request keeps running, but its terminal approval UI is no longer visible. This explains the isolated local terminal timeout without requiring an IPC message-loss hypothesis.

Disabling notifications, optional-argument masking, native reply batching or all native batching independently does not resolve the isolated case. Unshipped restoration/visibility/generation diagnostics also fail. Logging changes timing and can make the scenario pass; recursive console tracing and an interrupted experiment are explicitly excluded. These diagnostic packages are never performance candidates.

The correction makes the smoke-test extension write a profile-local marker **after** the explicit Local chat command completes. `openSession` clears the marker before each command and waits for it before sending the first prompt, with a bounded 60-second error if completion never arrives. Product code, response assertions, enabled tests and mock responses are unchanged. The patch is applied identically to baseline and candidate. Its original/modified file hashes are recorded in a sidecar artifact and in the root paired result. [Benchmark driver change](https://github.com/SimonSiefke/vscode-memory-leak-finder/commit/9297e6e3c6bf7604d4ea839d6cee1f036a7c9f61).

The exact unmodified `5f2` package passes four corrected-harness local terminal checks: the initial check and all three preplanned independent repeats. Exact upstream `4df` and current ACK `38b` packages also pass, for six passing corrected-harness checks with unchanged assertions and no retries. These are functional controls, not smoke timing estimates. The current candidate ZIP/archive/product commit were verified before running; native buffer pools and production RPC code are unchanged by the harness patch.
